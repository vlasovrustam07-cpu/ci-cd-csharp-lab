## 2. Базовая функция

`CalculatorApp/Calculator.cs` (начальная версия):

```csharp
namespace CalculatorApp
{
    public class Calculator
    {
        public int Add(int a, int b)
        {
            return a + b;
        }
    }
}
```

`CalculatorApp/Program.cs` выводит результат работы функции:

```csharp
Calculator calc = new Calculator();
Console.WriteLine("Калькулятор: 2 + 3 = " + calc.Add(2, 3));
```

```text
$ dotnet run --project CalculatorApp
Калькулятор: 2 + 3 = 5
```

## 3. Проект модульных тестов

Проект `CalculatorApp.Tests` создан по шаблону **Тесты xUnit**, в него добавлена
ссылка на проект `CalculatorApp`. Первый тест:

```csharp
[Fact]
public void Add_ReturnsCorrectSum()
{
    Calculator calc = new Calculator();
    int result = calc.Add(2, 3);
    Assert.Equal(5, result);
}
```

## 4. Настройка GitHub Actions

Файл `.github/workflows/dotnet.yml` (шаблон .NET):

```yaml
name: .NET CI  # Название workflow

on:
  push:        # Запускать workflow при пуше в ветку main
    branches: [ "main" ]
  pull_request: # Запускать workflow при создании pull request в ветку main
    branches: [ "main" ]

jobs:
  build:
    runs-on: ubuntu-latest  # Виртуальная машина с Ubuntu

    steps:
    - uses: actions/checkout@v5  # Клонирование кода репозитория

    - name: Setup .NET
      uses: actions/setup-dotnet@v5  # Установка .NET SDK
      with:
        dotnet-version: '8.0.x'  # Версия .NET SDK

    - name: Restore dependencies
      run: dotnet restore  # Восстановление зависимостей проекта

    - name: Build
      run: dotnet build --no-restore  # Компиляция без повторного restore

    - name: Test
      run: dotnet test --no-build --verbosity normal  # Запуск модульных тестов
```

Отличия от листинга в методичке: используются `actions/checkout@v5` и
`actions/setup-dotnet@v5` вместо `@v3`. Старые версии рассчитаны на Node.js 16/20,
который GitHub объявил устаревшим и выдаёт для них предупреждение; v5 работают
на Node.js 24.
`dotnet test` запускается без повторной сборки и с подробным выводом списка тестов.

## Вывод

Настроен конвейер непрерывной интеграции: при каждом push и Pull Request в `main`
GitHub Actions восстанавливает зависимости, собирает решение и запускает модульные
тесты. Каждый новый тест добавлялся отдельной задачей и отдельной веткой, и в `main`
попадал только после успешного прогона CI.
